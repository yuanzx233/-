# Day 1 技术验证结论

验证日期：2026-07-28

## 1. 验证范围

本仓库提供可重复运行的技术探针：

```powershell
python tools/tech_spike.py
python -m unittest tests/test_tech_spike.py
```

探针生成 8 份标准 ASCII DXF 正向样本、2 份异常样本，并验证 DXF 解析、PNG 场地预览、OBJ 三维体块、PPTX 和 PDF 输出。

## 2. 结论摘要

| 能力 | 结论 | MVP 决策 |
|---|---|---|
| 标准 DXF | 可行，但必须限制实体和图层约定 | 首期支持 ASCII DXF、单一闭合 `LWPOLYLINE` |
| 场地计算 | 面积、周长、边长和包围盒可稳定计算 | 入库统一为毫米，用户必须确认单位 |
| 图像预览 | 可由结构化边界生成 PNG/SVG | 预览不作为几何真值，内部 JSON 才是真值 |
| 效果图 | 本地探针只验证图像产物链路，不代表生成质量 | 通过供应商 Adapter 异步接入，保留参数与版本 |
| 三维输出 | 从边界挤出 OBJ 体块可行 | MVP 先交 GLB/OBJ，SKP 不作为阻断项 |
| PPTX | `python-pptx` 可生成可编辑文件 | 固定模板、限制文案长度、逐页渲染抽检 |
| PDF | ReportLab 可独立生成；PPT 转 PDF 仍需生产转换服务 | MVP 允许独立 PDF 降级路径 |

## 3. DXF 验证边界

正向样本覆盖矩形、长条、梯形、L 形、五边形、带道路/入口图层、米制与毫米制元数据。异常样本覆盖未闭合边界和多地块边界。

当前探针是验证性解析器，不应直接作为生产解析器。生产实现建议使用 `ezdxf` 并增加：

- `$INSUNITS`、块、旧式 `POLYLINE`、弧段 bulge、文本编码与坐标精度处理。
- 闭合容差、自交检测、重复点清理、洞口与多地块策略。
- 大文件资源限制、恶意输入检测和超时隔离。
- 图层映射置信度、人工纠错与原始/推断/用户输入的来源标记。

## 4. 主要风险与应对

1. **单位错误导致全链路失真**：上传时强制选择单位；面积数量级异常时阻断确认。
2. **闭合标记不等于几何有效**：增加首尾容差、自交和最小边长校验。
3. **效果图与平面不一致**：先构造统一体量和开口约束，再生成多视角；不从单张图反推完整模型。
4. **SKP 直接写出不稳定**：MVP 交付 GLB/OBJ，后续用 SketchUp 插件或受控转换服务。
5. **PPT 转 PDF 环境差异**：固定字体包和渲染镜像；PPTX 与 PDF 分别做自动和人工抽检。
6. **异步任务重复执行**：所有任务以项目、输入版本、任务类型和参数哈希生成幂等键。
